# Decisions

Recorded 2026-10-11 during planning. Reasons are in [DESIGN.md](DESIGN.md) §13 and [kam-api/FeatureKamApi.md](kam-api/FeatureKamApi.md) §4.

| ID | Decision | Outcome | Why |
|---|---|---|---|
| D1 | Live data from KAM | Cursor pull over REST, polled on intervals set in kammon.yml (1-2 s by default, D24) | Plain REST, no streaming, easy recovery |
| D2 | After a KAMmon restart | Memory only; backfill from KAM's ring; history start is labelled | No database or files to maintain |
| D3 | Admin versus web viewer | One listener, roles by user; admin power needed a request from the same computer until D31 withdrew that check | One port, no way for a remote visitor to reach admin routes (the reason then) |
| D4 | KAM endpoints | A separate monitoring listener (8766); scripts stayed on 8765. Superseded 2026-10-23, see D28 | The existing script API stays untouched |
| D5 | Modem changes | Apply, then save to `kam.yml` | One source of truth; the reset probe reuses saved values |
| D6 | Room clients | List and remove; protocol role is read-only | No new radio-side permission model |
| D7 | What viewers see | Per-channel allow list for text | Public channels may be shared, private ones stay private |
| D8 | History | 8192-event ring in KAM; 24 h chart grows with KAMmon uptime | Small memory, no second aggregation path in KAM |
| D9 | UI technology | Go templates and htmx; charts are server-drawn SVG | One binary, no build step |
| D10 | Script tools | Dry run plus in-memory run information | Makes "build and test a script" real |
| D11 | Web roles versus room roles | Preserve existing room behavior; withdraw pinned roles | KAMmon web permissions are independent of MeshCore room authentication |
| D12 | KAM monitoring listener default | On by default, loopback only | Easiest setup; `monitor.enabled: false` removes it |
| D13 | List responses | Named envelopes and `[]` for empty lists | Explicit without generic wrapping machinery |
| D14 | Event pagination | Add `next_after`; keep `last_seq` as the ring head | Prevent clients skipping pages |
| D15 | Failed modem changes | Restore on any apply/save failure; pause TX if recovery fails | Never hide a runtime/configuration disagreement |
| D16 | Signal reporting | Always enabled | Preserve useful measurements without another setting |
| D17 | Recording | Short lock, bounded copy | No separate queue or worker; no claim of zero waiting |
| D18 | Dry runs | 500 ms default, 3000 ms maximum, one at a time, 16 replies / 4096 bytes | Bounded tests without asynchronous jobs |
| D19 | Per-packet SNR and RSSI | Measured and stored with every event and stored message, never shown on packet pages, channel message lists or message footers | KAM listens through a local repeater: signal strength describes the hop to KAM, not the sender, so the numbers carry no message |
| D21 | Room posts and client labels | Admin only; viewers see room summaries only | Client keys and room posts are private monitor data |
| A2 | Events | Metadata only; message text is fetched on demand | Keeps text out of the ring |
| D20 | Manuals | Markdown in `web/manuals/`, rendered once at startup, served public at `/manuals/` with `Cache-Control: public`; pages share the app shell, sidebar, pager and theme cookie. Removed 2026-10-18, see D23 | No build step or dependency; beginners can read without logging in; shared caches (Cloudflare) hold the static bytes, one theme across app and manuals |
| D23 | Manuals removed | The manuals, their public `/manuals/` route and the sidebar Help section are gone from the interface: the sidebar keeps only its navigation list, `web/manuals/`, `internal/manuals` and the theme initializer for cached manual pages are deleted, and the static cache-buster lives in `internal/web` | The manual display cluttered the app; the simplest thing is a screens-only monitor, and the plain-words explanation stays in README.md and docs/ (2026-10-18) |
| D24 | Poll and age knobs in kammon.yml | `poll:` sets how often the poller reads KAM (`events`, `status`, `rooms`, `channels`, `scripts`), each read's `timeout`, and the pause after a 404 (`not_served`); `freshness:` sets `stale_after` and `down_after` (MON-DS-13); missing lines keep the defaults: the §5 intervals, 3 s, 10 minutes, 10 s, 2 min | Some nodes want a slower poll, and the old-data labels should match a poll that is slower or faster than the default bands (2026-10-18) |
| D25 | Traffic row details | One click on a row opens or closes a detail line under it with the packet's full record (MON-TR-14); the details are server-rendered, toggled client-side, and an open line survives the two-second refresh | No new endpoint and no KAM change; SNR and RSSI stay out (D19) and the viewer rules hold untouched (2026-10-18) |
| D26 | Sidebar navigation | One standard list of navigation items in the sidebar: no Workspace or Help section labels and no collapsible groups; the section state-restore script (`web/static/nav.js`) went with them | With Help gone (D23) the single collapsible section grouped nothing and only added a label and a toggle; the plain list is the simplest thing (2026-10-23) |
| D27 | Term for the API on 8766 | KAMmon's docs call it the KAM API; the old wording that named the API after KAMmon is out of prose. KAM's contract has taken the same name (KAM's D19, same day); only the `kam_monitor_url` key keeps the old word | The old wording read as the API of KAMmon, the KickAss MeshCore Monitor (2026-10-23) |
| D28 | One KAM address | KAM serves script routes on the same listener as the KAM API (8766); `kam_scripts_url` is removed from `kammon.yml` and the coming scripts client will use `kam_monitor_url` | KAM closed port 8765 with its unified listener (its D1); a second URL knob would name nothing (2026-10-23) |
| D29 | Where the editor's source comes from | The store's script snapshot carries no source; the editor loads a script's source straight from `GET /scripts/{id}` in the admin's own request when it opens, and every admin action (validate, dry run, save, enable, disable, recover, delete) is one call from that request to KAM | The list pages read the store only (MON-DS-1); keeping KAM's script texts out of the store's memory too keeps it bounded (DataStore.md §3), and a viewer is never sent source either way (MON-AU-4) (2026-10-23) |
| D30 | The dry-run capability check | Each editor open probes `POST /scripts/dry-run` with an empty body and no memo: a KAM with the route answers 400 or 422 and KAMmon shows the button; a 404 or 405 leaves the button out and says "Needs a newer KAM." — and the same answer on the click itself (KAM restarted older, or the probe raced) says the same. The 405 is an older KAM's usual answer: its `/scripts/{id}` routes cover the path, so KAM's mux refuses the method before any route speaks | The route is phase 5, not all KAMs have it, and the button must never lie; the empty probe runs nothing and costs KAM one validation (MON-AU-20) (2026-10-23) |
| D31 | Access rules by transport | None: the session's role alone decides power, on every request, from any address; the old loopback rule and its view-only notice (the withdrawn MON-AX-9 and MON-AX-10) are out of the code, and the 403 page no longer says "on this computer" | KAMmon is written for the enthusiast, like KAM: it imposes no hosting or transport restrictions of its own, so the operator can choose what fits their setup. Serving beyond the LAN is the operator's decision and responsibility, done with the proper services in place that provide TLS (HTTPS through a reverse proxy, or `tls_cert`/`tls_key`); KAM's own listener stays loopback-only regardless (2026-10-23) |
| D32 | The script id of a create | KAMmon sends the name as typed as the id: KAM's create takes the id from the body (its APIdetails example carries id and name), and a later rename keeps the id while the name changes | KAMmon invents no id scheme of its own; the words the operator types are the identity on the wire too (2026-10-23) |
| D33 | The server statistics block | The server's host snapshot lives in a sidebar block under the node block, for the administrator only: CPU load averages, red/blue memory and disk bars drawn as numbers-only SVG, and the database and WAL sizes, each row's full numbers on hover. Its only datasource is the opt-in `system` section of `GET /v1/status?system=true`, which the poller's status read already asks for; the block reads the store, adds no request of its own, and leaves sections the OS cannot measure out entirely (MON-SV-1..3) | The node block answers "is the link well?"; this block answers "is the box well?" at a glance without a terminal. The numbers ride in the snapshot KAMmon already reads and are cached inside KAM at most once per 5 s, so a page view costs KAM nothing (2026-11-08) |
| D38 | Sidebar links to the hosted manuals | The sidebar's last entry, **Manuals**, opens https://mauricekremer.github.io/kammon/ in a new browser tab (`target="_blank" rel="noopener"`); it is a plain external link offered to every role, it has no route of this server, and it is never the active item | The app stays screens-only (D23) while a beginner gets from the app to the plain-words explanations in one click; the site itself goes live when the manuals PR has merged (2026-11-21) || D34 | The sidebar's admin pages | Rooms, Automations and the KISS modem join Accounts as administrator pages: their routes (`/rooms`, `/ui/room-metrics`, `/automations`, `/ui/script-list`, `/modem`) answer 403 to any other role, and their sidebar items carry a grey lock at the right edge | Rooms name remembered clients, scripts run on the node, and the modem page controls the radio: that is the administrator's domain. Hiding the link is only marking; the route is the guard (MON-AX-12) (2026-11-08) |
| D35 | The sidebar's icons | Every sidebar item leads with an icon of its page from the vendored sprite (activity, radio-tower, hash, messages-square, users, workflow, cpu); admin-only items close with a grey lock | A dense console reads by shape first; the icons ride the link colour, so the list stays calm (2026-11-08) |
| D36 | Static assets revalidate | `/static/` answers `Cache-Control: no-cache` instead of a four-hour `max-age`; the version query (`?v=kammon-14`) still names each file's generation | A browser cache kept answering an unchanged versioned URL with retired bytes (Safari 27, found by measuring inside the running browser), and revalidating 21 kB on loopback costs nothing (2026-11-08) |
| D37 | The channel utilization chart's health zones | The overview's channel utilization chart paints the shared bands as background washes (calm under 10 %, busy 10 to 20 %, congested over 20 %) with a dashed hold-back line at 25 %, where a LoRa channel's backoffs grow; the axis never ends under 30 % of one slot and grows a whole 10 % band, so busy and congested always fit; the thresholds are said in words below the chart and in the chart's text alternative (MON-OV-6) | The community reads a channel's utilization against these bands, and colour alone is not meaning (rule 6), so the words carry them too; the floor keeps the zones on a quiet channel instead of letting the axis shrink under 30 % and hide them (2026-11-08) |
| A3 | Repositories | KAM and KAMmon are separate repositories | KAM must work without KAMmon; KAM's packages are `internal/` |
| D39 | Where the Adverts page gets its data | KAM exposes its existing `adverts` table as `GET /v1/adverts` (built in KAM first, contract before code); KAMmon's poller reads it every 60 s, keeps a bounded copy (1000 nodes) with its own freshness, and the page reads only the store | The table already holds the newest advert per public key for 30 days, so no reception history, no migration and no new ingestion cost; public keys make identity exact, which a nickname never was (2026-11-22) |
| D40 | What the advert plan is | A descriptive record: an inventory table, an offline map and a copyable plain-text plan. It contains no recommendations, scores or "you should" lines; every limit (advertised, not verified; hop count, not a path; clue, not identity) is said in words | The operator asked for analysis and a plan without advice; the data can describe a mesh but cannot justify an action. Keeping the wording factual keeps the page honest (2026-11-22) |
| D41 | The advert map's basemap | Natural Earth 1:110m land and country borders, embedded in the binary and drawn as numbers-only SVG in an equirectangular projection fitted to the nodes; nodes without a position sit on 15 km hop bands around `location` from `kammon.yml`; OpenStreetMap is offered as a per-node link only | No tiles, no CDN and no third-party request: the page works offline like the rest of KAMmon. A link gives the operator the real map without making the monitor depend on it. The 15 km band is an assumption, so the page says so (2026-11-22) |

| D42 | The advert map's basemap and projection | Natural Earth 1:50m land and country borders, projected once at generate time to Web Mercator (`scripts/gen-basemap.py`), shipped as one generated SVG asset (`internal/web/basemap_svg.go`) served at `/static/basemap.svg` with an asset-version ETag and drawn by one same-origin `<use>` reference; dot colours carry the table's last-heard indicator, and a scale bar with a degree grid is drawn and its figures said in words | The 1:110m coastlines read as a sketch at country zoom. Serving the basemap as one cached asset keeps the projected map out of every page view and poll swap (1:10m would be waste there, and 0.025-unit path simplification is invisible at 1 px). Mercator keeps the hop bands honest at any zoom and matches the maps the OpenStreetMap links open; it supersedes the 110m equirectangular choice of D41 (2026-02-14) |
| D43 | The adverts map's default frame and bad coordinates | The default frame is the country at `location` from `kammon.yml`: the generator embeds 1:110m admin-0 polygons plus tiny-country points, the page fits the ring that holds the point, and the node fit remains the fallback when `location` is missing or unmatched. Adverts within ±0.01° of 0°N 0°E are a missing GPS fix: kept in the table, never plotted, never shaping the frame. Nodes outside the frame are counted, not drawn, and coincident dots step aside deterministically | Advertised coordinates cannot be trusted to define the view: one bad fix stretched the old fit to a world map. The country answers "default area at country level" without geocoding services, offline, and the containing ring keeps overseas parts out of the frame. Null Island is the usual no-fix value — the same rule MeshCore Open applies to its position history (2026-02-14) |
| D44 | The adverts map's default width and zoom control | The default frame is about 260 km around the configured location — never wider than the holding country's ring; the node fit stays for a missing or unmatched `location` — and `+`/`−` buttons step the frame ×2 from a ¼ level to 16×, re-rendering through htmx into the same live region with `?mapzoom=` carried in its URL so the poller keeps it; the centre stays the configured node | At country scale a local mesh reads as one dot cluster; the operator wants the working area as the default and a quick zoom for detail. Rendering stays server-side (A3), and the zoom is the state in the URL the poll already refetches, so no client memory and no new script (2026-02-14) |
| D45 | The adverts map's detail and city names | The basemap gains Natural Earth 1:50m lakes, a 0.012-unit path corridor (0.005 for lakes, whose narrow rings collapse otherwise), and the full Natural Earth town list — 10m populated places, 7,300-odd entries — drawn as labelled dots filtered to the frame, most major first, a minimum label distance apart, at most 24; the map section header reads Map | At the zoomed frames (down to about 12 km across) the old 2.8 km corridor cut visible corners, and city names orient the operator. The names are vendored Natural Earth data, not radio text, so rule 5's escaping guarantee stays untouched; a first lakes pass at the wide corridor self-intersected and spilled, which is why lakes keep the fine corridor (2026-02-14) |
| D46 | The advert map's dot interaction | The printed dot numbers are gone: dots are finer, announce their row number to assistive tech, and hover, focus and click open server-escaped cards beside the SVG — mini on hover or focus, full when pinned by click or Enter, one page script (`web/static/map.js`) delegating the events so the 60 s refresh rebinds nothing, any other click or Escape un-pinning | The operator reads a dot without counting table rows. The SVG stays numbers-only so radio text stays out (rule 5), while the cards carry the name and details from the same escaped template rows — the drawing never moves into the browser (A3): it only reveals (2026-02-14) |
| D47 | The adverts map's interactive camera | The map opens on a 100 km radius around the centre — the mean latitude and longitude — of the nodes that advertised a position (the whole frame without them), served as the SVG's opening `viewBox` with the frame's size as data attributes; `web/static/adverts-map.js` moves that viewBox client-side inside the frame: mouse and touch drag with momentum, two-finger pinch, scroll wheel at the pointer, `+`/`−` buttons stepping ×2 between the whole frame and 16× the opening view (a bound disables its button), and `Reset` returning to the opening view; the camera rides no URL and survives the 60 s refresh, and a drag's trailing click never lands on a dot (supersedes the zoom control of D44, keeps its frame) | A still press must stay an ordinary click on its dot (MON-AD-16), so nothing captures the pointer; the server keeps drawing the whole frame (A3) and the script only moves its window into it — no re-render, no URL state, and the operator's place survives the poll that re-renders the map (MON-AD-15) (2026-11-22) |
| D48 | The adverts map plots advertised positions only | The map draws only nodes with a valid advertised position. Nodes that advertised no position, and adverts within ±0.01° of 0°N 0°E, are never placed by a hop-count or any other estimate: they stay in the table and are counted in the map's notes. The hop bands, the hollow probable dots and their legend entries are removed, so every dot is a coordinate the node itself chose (supersedes the hop-band placement of D41 and the probable dots of MON-AD-6/MON-AD-7) | An estimated distance on a geographic basemap reads as a measured place, which is not what the data says. Keeping the map strictly to advertised coordinates makes it clean and accurate, while the count preserves the honest label that nodes were left out (rules 5 and 6) (2026-11-22) |
| D49 | The adverts map's marker clustering | Nearby dots group into numbered SVG badges whose radius and label are constant on screen; a badge click (or Enter) glides the camera into its members' bounds, and at the deepest zoom dots that still overlap fan out along a golden-angle spiral with thin legs home. Grouping is a native, screen-space union-find over the existing dots in `web/static/adverts-map.js`, recomputed after each camera move; markers keep one screen size instead of scaling with the viewBox. No Leaflet or Supercluster dependency is added; the map stays one offline server-drawn SVG (supersedes the marker scaling implied by D47's camera) | The map already has a bespoke viewBox camera and no tiles, so Leaflet would add a second rendering model and break the offline single-binary design. A small native pass keeps the SVG numbers-only (rule 5), leaves A3's server drawing intact, and still gives the requested cluster badges, smooth bounds zoom and spiderfy (MON-AD-17) (2026-11-22) |
| D50 | The adverts map opens and resets on the configured node | The opening view is a 100 km radius centred on `location` from kammon.yml — Emmen, 52.77920 N 6.90690 E in the demo — held inside the frame. The `Reset` button glides smoothly back to that same opening view instead of jumping or recomputing a centre (supersedes the located-nodes opening view of D47) | "Your node" is the operator's fixed reference, so the map should open where the operator is rather than drifting with whichever peers advertised last; it also makes Reset a stable, named place. The located-nodes centre remains a sensible fallback for a config without `location`, and the smooth reset keeps the existing camera language (MON-AD-15) (2026-11-22) |
| D51 | The adverts map's city labels | Natural Earth city names draw at a constant 9.5 screen px, normal weight, muted grey, with a high-opacity background-coloured halo and a small muted dot. | D52 | The adverts map's cluster z-order and animated spiderfy | Cluster badges, their hit areas, spider legs and base lines live in SVG layers inserted *before* the home marker and node circles, so a badge never renders over a standard dot.
