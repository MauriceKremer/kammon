One node, watchable

Keep an eye
on the mesh.

KAM turns MeshCore radio traffic into records, rooms and scripts on one small machine. KAMmon is its calm console: sign in from a browser and watch your node work — what the radio hears, how the channel is used, and what the rooms and scripts are doing.

Meet KAMmon → Explore the manuals
Statusworking monitor Demo mode, login, and the Overview, Traffic, Channels, Rooms and Automations pages are built; the KISS modem and Accounts pages follow. KAM's core is implemented and covered by CI; radio settings stay the operator's responsibility.

Two programs, one machine

Catch it. Keep it. Watch it live.

KAM does the radio work and works fine without KAMmon. KAMmon adds the screens and the login, and owns nothing on KAM's side — the boundary between them is KAM's local API.

01 / LISTEN

Take the radio seriously

A KISS modem on USB feeds one Go program: supported packets decoded, channel keys applied, signal data attached where the modem reports it.

02 / REMEMBER

Make messages last

Decoded traffic goes into local SQLite, together with installed scripts and room state. No cloud, no second database server.

03 / AUTOMATE

Let small ideas run

Starlark scripts react to group texts or fire on a timer or cron schedule — reply to a channel, fetch a service, post into a room.

04 / OBSERVE

Watch it from a browser

KAMmon reads the local API and draws it plainly: honest labels, two web roles, memory-only history that KAM never waits for.

Try it in one minute. Demo mode starts a fake KAM with generated traffic, so no radio is needed. Sign in as admin/admin or viewer/viewer.

go run ./cmd/kammon -demo
