## Sessions and activity (implemented)

- A client is a remembered, per-room public-key session, not a live connection. Role, sync cursor, client replay timestamp and route are persisted; shared secrets are recomputed. `lastActivity`, pending ACK and failures are runtime-only. Restored activity starts at zero. Sources: [internal/room/room.go](../../../kam/internal/room/room.go#L40), [internal/room/room.go](../../../kam/internal/room/room.go#L75), [internal/room/room.go](../../../kam/internal/room/room.go#L152), [internal/db/rooms.go](../../../kam/internal/db/rooms.go#L24).
- `Service.Stats().Clients` counts all loaded/created sessions across rooms, including clients never heard from since restart. It decreases on removal, not on inactivity. Calling this **online** or **active clients** is misleading. Sources: [internal/room/service.go](../../../kam/internal/room/service.go#L216), [internal/room/room.go](../../../kam/internal/room/room.go#L146), [internal/room/room.go](../../../kam/internal/room/room.go#L279), [internal/room/room.go](../../../kam/internal/room/room.go#L296).
- Push eligibility means activity has been seen at least once this run, fewer than three failures, and no pending push; it has no recent-activity time window. There is no inactivity/session expiry in these handlers. A full table evicts the least recently active non-admin; admins are protected. Sources: [internal/room/push.go](../../../kam/internal/room/push.go#L27), [internal/room/room.go](../../../kam/internal/room/room.go#L263), [internal/room/room.go](../../../kam/internal/room/room.go#L283).

### What updates last activity

`lastActivity` uses the server's processing time (`s.now()`), not the sender's clock. Sources: [internal/room/service.go](../../../kam/internal/room/service.go#L237), [internal/room/room.go](../../../kam/internal/room/room.go#L49).

| Accepted input | Activity / failure behavior | Evidence |
|---|---|---|
| Password-authorized login | Updates activity; resets failures and pending push; assigns role and cursor. Replay checks apply. | [internal/room/room.go](../../../kam/internal/room/room.go#L434) |
| Blank-password resume by known key | Updates activity but preserves role, replay timestamp, cursor, pending push and failures. Flood login still clears the route in the common path. | [internal/room/room.go](../../../kam/internal/room/room.go#L425), [internal/room/room.go](../../../kam/internal/room/room.go#L462) |
| Valid decrypted PATH | Updates activity and route; does not itself reset failures. An embedded matching ACK can reset them. | [internal/room/room.go](../../../kam/internal/room/room.go#L508) |
| Plain text or CLI text passing length/type/replay checks | Updates activity and resets failures, even for retries, empty text, disallowed posting roles, unsupported CLI commands or subsequent storage failure. Not every activity event is a stored post. | [internal/room/room.go](../../../kam/internal/room/room.go#L524) |
| REQ passing length/replay checks | Updates activity, replay timestamp and resets failures before checking request type or direct route. Unsupported requests and non-direct keep-alives can therefore count as activity, despite getting no response. | [internal/room/room.go](../../../kam/internal/room/room.go#L599) |
| Matching push ACK (bare or multipart) | Clears pending/failures and advances cursor; does **not** update activity. A PATH carrying it separately updates that PATH sender's activity. | [internal/room/room.go](../../../kam/internal/room/room.go#L317), [internal/room/service.go](../../../kam/internal/room/service.go#L252) |

Push ACK timeout is 12 seconds for flood, or `4 seconds + 2 seconds * (encoded hop count + 1)` direct. Three actual timeout failures pause pushes and discard a known route, but do not delete the session or prove the client is offline. A push still queued is cancelled without a failure. Blank resume or PATH alone need not unpause a client, despite the docs' broader wording about activity. Sources: [internal/room/push.go](../../../kam/internal/room/push.go#L14), [internal/room/push.go](../../../kam/internal/room/push.go#L53), [internal/room/push.go](../../../kam/internal/room/push.go#L101), [docs/FeatureRoomServer.md](../../../kam/docs/FeatureRoomServer.md#L383).

## Names and roles

- **Room display name:** configured room `name`, advertised to clients; changing it requires restart today, and clients retain the old name until the new advert arrives. Sources: [manuals/FeatureRoomServer.html](../../../kam/manuals/FeatureRoomServer.html#L183), [manuals/FeatureRoomServer.html](../../../kam/manuals/FeatureRoomServer.html#L371).
- **Client/author display names:** unavailable as structured room data. Login carries timestamp, cursor and password; sessions store public keys, and posts store author key plus body, not a name. Any text that looks like a nickname is not a dedicated identity field. Use a shortened key with the full key available. A future name lookup from adverts/contacts is a proposal, not established by these allowed sources; names may be missing or stale and must remain optional. Sources: [internal/room/room.go](../../../kam/internal/room/room.go#L415), [internal/db/rooms.go](../../../kam/internal/db/rooms.go#L12), [internal/db/rooms.go](../../../kam/internal/db/rooms.go#L24), [internal/db/rooms.go](../../../kam/internal/db/rooms.go#L54).
- **Roles:** `GUEST=0`, `READ_ONLY=1`, `READ_WRITE=2`, `ADMIN=3`. All can receive posts; only 2 and 3 can post in KAM. Admin also has eviction protection, but not working over-the-air administration. Login assigns 3 for admin password, 2 for guest password/open room, or 0 for the read-only fallback. Role 1 exists and can be restored from storage, but no current supported login assigns it. Sources: [internal/room/room.go](../../../kam/internal/room/room.go#L18), [internal/room/room.go](../../../kam/internal/room/room.go#L242), [internal/room/room.go](../../../kam/internal/room/room.go#L543), [internal/room/push.go](../../../kam/internal/room/push.go#L37), [manuals/FeatureRoomServer.html](../../../kam/manuals/FeatureRoomServer.html#L281).
- **Direct admin role editing: not supported.** Role changes currently require a successful password-authorized login; blank resume retains the role. A DB upsert accepting a role is internal persistence, not an operator editing API, and is not a live-state mutation mechanism. Management endpoints, immediate API role changes, status/telemetry/access-list replies are deferred; CLI text receives neither reply nor ACK. Sources: [internal/room/room.go](../../../kam/internal/room/room.go#L425), [internal/room/room.go](../../../kam/internal/room/room.go#L459), [internal/db/rooms.go](../../../kam/internal/db/rooms.go#L255), [docs/FeatureRoomServer.md](../../../kam/docs/FeatureRoomServer.md#L360), [docs/FeatureRoomServer.md](../../../kam/docs/FeatureRoomServer.md#L366), [docs/FeatureRoomServer.md](../../../kam/docs/FeatureRoomServer.md#L377), [manuals/FeatureRoomServer.html](../../../kam/manuals/FeatureRoomServer.html#L105).

## UI recommendations (proposed, not current API)

| UI label | Recommended definition and availability |
|---|---|
| **Remembered clients** | Per-room session count; do not label the existing aggregate `Stats.Clients` online. A per-room snapshot/export would be new. |
| **Last activity** | Latest server-observed qualifying client input for this room; client rows show their own value. Show unknown/not heard since restart for zero. Exporting or persisting it is new. If ACKs should count as heard, add explicit receipt tracking rather than silently reinterpreting existing `lastActivity`. |
| **Last post** | Latest retained post insertion time, shown separately from activity. Protocol `post_ts` is usable for ordering, but is not exact wall-clock receipt time. |
| **Posts last hour** | Count committed posts per room with `created_at` in `(now - 3600, now]`; exclude retries, empty/disallowed/failed posts. Query the retained DB, not the bounded backlog cache or lifetime `PostsAccepted` counter. This query/export is new; label it retained posts if pruning can remove recent rows, or retain independent event counts for exact historical totals. |
| **Clients heard last hour** | Distinct public keys per room with qualifying server-observed input in `(now - 3600, now]`. With existing runtime activity this is only measurable since startup and for retained sessions; report partial history after restart. To include evicted clients or survive restart requires separate observation history. This is proposed and is not an online/presence guarantee. |
| **Push state / role** | Show awaiting ACK, paused after failures, or not heard this run separately from activity; display role read-only. Do not provide a functional role editor until a worker-owned management mutation and persistence path exists. |

Implemented monitoring is only service-lifetime aggregate counters and total remembered clients in `Stats`; there are no hourly metrics, activity/name fields or per-room/client snapshots in that interface. The docs explicitly say counter export and management endpoints are open. Storage offers total `CountPosts` and limited `LatestPosts`, not hourly counts.
